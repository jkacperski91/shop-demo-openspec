---
name: sync-api-schema
description: Restart the Spring Boot backend and regenerate frontend/src/api/schema.d.ts after changing backend DTOs, request/response models, or controller endpoint signatures. Use right after finishing such backend edits, before doing frontend work that depends on the updated API shape.
---

Keep `frontend/src/api/schema.d.ts` in sync with the backend's live OpenAPI document. The file is generated by `yarn generate:api`, which runs `openapi-typescript` against `http://localhost:8080/v3/api-docs` — so it can only pick up a backend change once a backend serving that change is actually running. The backend has no hot reload (no devtools), so a real restart is required; editing a controller or DTO and leaving the old process running will regenerate the *old* schema.

**When to run this**

Trigger after backend edits that change the API surface:
- Fields added/removed/retyped on request or response DTOs
- New, removed, or changed `@RestController` endpoints (path, HTTP method, path/query params)
- Changed controller method signatures (different request/response type)
- Enums or nested records referenced in a request/response body
- Validation annotations that affect the generated schema (e.g. `@NotNull`, `@Size`)

Do **not** trigger on service/repository/persistence-only changes, test-only changes, or mid-edit (wait until the API-affecting change is actually finished, not after every intermediate save — a restart is not free).

**Steps**

1. **Check if the backend is already up:**
   ```bash
   curl -sf http://localhost:8080/actuator/health
   ```
   - No response → skip to step 3.
   - Responds → go to step 2.

2. **If something is already running on :8080, decide whether it's safe to restart:**
   - If you (Claude) started this backend earlier in this same conversation, you may restart it directly.
   - If you have no record of starting it — it was already running before you touched anything, likely a terminal the user has open and is watching — **stop and ask the user for confirmation** before killing it. Don't silently tear down a process you don't own.
   - Once clear to proceed, stop it. From PowerShell:
     ```powershell
     Get-NetTCPConnection -LocalPort 8080 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
     ```
     Or if you hold the background task handle from starting it yourself, stop that task directly instead of hunting for the port.

3. **Start the backend in the background** (from `backend/`):
   ```bash
   ./gradlew bootRun
   ```
   Run this as a background task — don't block the foreground on it.

4. **Wait for a clean boot by polling health, not by guessing a fixed delay:**
   ```bash
   until curl -sf http://localhost:8080/actuator/health | grep -q '"status":"UP"'; do sleep 2; done
   ```
   Give it a reasonable ceiling (~90s covers a cold Gradle daemon). If it doesn't come up in time, stop and report the failure — check the `bootRun` output for a compile error or port conflict rather than retrying blindly.

5. **Regenerate the schema** (from `frontend/`):
   ```bash
   yarn generate:api
   ```

6. **Format it** (from `frontend/`):
   ```bash
   yarn format
   ```
   `openapi-typescript`'s raw output doesn't match this repo's Prettier style (double quotes/semicolons/4-space indent vs. the committed single-quote/no-semi/2-space style) — skipping this turns a one-line schema change into a 300+ line diff and fails `yarn lint`. `yarn format` reformats the whole frontend but only touches files that actually need it, so this is safe to run unconditionally.

7. **Confirm and summarize what changed:**
   ```bash
   git diff --stat -- frontend/src/api/schema.d.ts
   ```
   Report the new/changed endpoints or types. If the diff is empty, say so explicitly and double check the backend change actually reached the controller/DTO layer — an empty diff after a real API change usually means the regenerate ran against a stale/unrestarted backend.

8. **Leave the backend running** afterward for continued local development — mention it's up on `:8080` rather than tearing it down, unless the user asks you to stop it.

**Guardrails**
- Never kill a backend process you don't recognize as your own without asking first.
- Never hand-edit `schema.d.ts` — it's auto-generated; only ever produce it via `yarn generate:api` + `yarn format`.
- If `bootRun` fails to boot, report the actual error instead of retrying the restart loop.
- This skill is dev-workflow tooling only — it doesn't authorize backend changes themselves; those still need to trace back to an active OpenSpec change per `AGENTS.md`.
